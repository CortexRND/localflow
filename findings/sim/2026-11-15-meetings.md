# Meeting sim — 2026-11-15 (PR #19)

Protocol: `evals/meeting_sim/PROTOCOL.md`. It adapts the org's sim-testing playbook to LocalFlow; Cortex's G1–G13 gates don't apply here. Gates and thresholds were fixed before the first run.

## What ran
- **System under test:** the real FastAPI app via `TestClient`, at `27f2bba` (baseline) and `0577a73` (heading-skeleton fix). Every result file's commit was checked.
- **Model:** Ollama `llama3.2:3b`, the shipped default, CPU only, with the product's prompts unchanged.
- **Scenarios:** 6 scripted meetings × 3 repeats = 18 cells per SHA. 18/18 ran at each SHA; none crashed or timed out.
- **Audio and transcription:** fake. Each line is a tagged tone on its speaker's source, decoded by a scripted transcriber. The vendor scenario forces system audio to fail.
- **Jev** (`jev-1.14.0`, live) is a second judge. It's trusted for the answer and abstention checks, which scored 1.000 in today's calibration. The notes-faithfulness questions are new and uncalibrated, so they're advisory only.

## Findings
1. **Fixed: enhanced notes dropped the user's headings** in 12 of 15 baseline meetings. The 3B model wrote only the template sections, despite the "keep the user's structure" prompt. `0577a73` puts the user's heading lines into the prompt as a required skeleton, and M4 went 3/15 → 15/15. The one-shot repair retry in `summarize` never fired in these runs: every meeting made exactly 1 summarize call.
2. **Open: owner attribution errors from the 3B model** appear at both SHAs. Examples: the user's PR review credited to Omar or listed under "Yesterday", and the audit owner given to Kim when nobody owned it. Jev's advisory "contradicts" rate is 5/18 baseline and 11/18 after, but that judge question is uncalibrated and swung from 0.62 to 0.78 mean on the no-notes scenario, whose prompt is unchanged at both SHAs. So I'm treating it as model variance until a calibrated rerun says otherwise. Recommendation: run the same matrix with a larger local default model before changing the prompt again.
3. **Open: the same two facts were missed in 3/3 repeats at both SHAs:** the "icon set later" follow-up (written as "None recorded") and churn as the reason for rejecting $15. After the fix, one pricing run kept the user's headings but dropped the template Action Items (the Marcus/Friday owner) and wrote a "[Current Date]" placeholder.
4. **Minor: the 1:1 template writes its own title heading** ("# 1:1 with Jordan", echoed as "11"). The title is already added by `ObsidianWriter`, and the new "no title heading" line in the prompt is ignored by the 3B model. It's the only number M7 flagged as unsupported, so after adjudication there are 0 fabricated numbers.
5. **Chat:** 1 flake in 33 answerable questions (the answer was a bare "[00:20]"). Jev marked 0/33 answers as contradicting the truth. It flagged "Did we discuss salary?" as answerable from the sources, which is a yes/no framing difference, not a product error.

## Not exercised
Real STT and microphone, ScreenCaptureKit, long-transcript chunked summarize/merge and chat map-reduce (>2,500/4,000 words), native Hub UI, and larger or remote models.
